# Архитектурная спецификация: Двухуровневый тактический ИИ для HoMM III (VCMI)

## 1. Концепция и проблематика
Стандартные алгоритмы Reinforcement Learning (RL) и метод «в лоб» (PPO на плоском векторе из 12 000 признаков) терпят неудачу в пошаговой тактике из-за:
1. **Проблемы распределения наград (Credit Assignment Problem):** Сетка не понимает, какое конкретно микро-действие на 2-м ходу привело к победе на 15-м ходу.
2. **Отсутствия стратегической памяти:** Модели без иерархии действуют как «чистый рефлекс», не умея планировать фазовые переходы и комбинировать роли внутри одной армии.
3. **Разреженности данных (Sparsity):** Огромные карты признаков без выделения ролей требуют сотен миллионов боев для сходимости.

**Решение:** Разделение принятия решений на **два уровня** по аналогии с мышлением сильного игрока-человека:
- **Уровень 1: Стратегический Командир (Macro Director)** — делит армию на боевые группы, назначает роли стекам и управляет фазами боя.
- **Уровень 2: Тактический Исполнитель (Micro Executor)** — оценивает поле по 9 атомарным тактическим паттернам и генерирует узкий набор из 3–4 ходов-кандидатов.

---

## 2. Уровень 1: Стратегический Командир (Macro Director)

Командир срабатывает в начале боя и динамически переоценивает ситуацию после каждого ключевого события (гибель стека, спад угрозы, прорыв строя).

### 2.1. Динамические фазы боя (Battle Phases)
1. **Фаза Сдерживания (Containment / Defense):** Враг полон сил, угроза летунов/раша высока. Приоритет — плотная позиция, защита ядра, прием удара на расходники.
2. **Фаза Контратаки / Прорыва (Breakthrough):** Ключевые угрозы врага связаны или нейтрализованы. Строй размыкается, мобильные группы выходят на преследование.
3. **Фаза Дожима / Сейва (Mop-up / Zero-Loss Farming):** Исход решен, остался 1–2 слабых стека. Задача — затянуть бой для отстрела без единого удара в ответ или воскрешения павших.

### 2.2. Расчет боевых метрик и назначение ролей
Роль юнита **не зависит от его уровня в игре**. 1 Ангел может быть расходником, а 500 Скелетов — абсолютным ядром.

#### Формулы метрик:
1. **Доля в огневой мощи (Damage Share):**
   $$\text{DamageShare}(S) = \frac{\text{Count}_S \times \text{AvgDamage}_S \times \text{AttackMod}_S}{\sum \text{TotalDamage}_{\text{army}}}$$
   - Стек с $\text{DamageShare} \ge 60\%$ автоматически становится **`ROLE_CORE` (Ядро)**.

2. **Ценность потери (Loss Cost):**
   $$\text{LossCost}(S) = \text{GoldValue}(S) + \text{UtilityBonus}(S)$$
   - Если $\text{Count}_S = 1$ и юнит дешёвый $\to$ **`ROLE_BAIT` (Приманка)**.
   - Если $\text{Speed}_S \ge 10$ (летун/кавалерия) $\to$ **`ROLE_INTERCEPTOR` (Перехватчик / Диверсант)**.

#### Матрица 4 динамических ролей:
* **`ROLE_CORE` (Ядро урона):** Главный источник победы (Стрелки, массивный стек). Приказ: держать позицию, максимизировать урон, избегать ближнего боя.
* **`ROLE_BODYGUARD` (Телохранитель):** Тяжелая пехота. Приказ: перекрывать проходы, стоять смежно с `CORE`, принимать урон.
* **`ROLE_INTERCEPTOR` (Перехватчик):** Быстрый мобильный юнит. Приказ: первый ход — нейтрализовать/заблокировать чужих стрелков, связать босса.
* **`ROLE_BAIT` (Приманка / Расходник):** Единички. Приказ: забегать в зону угрозы врага, провоцировать трату его хода, снимать ответку.

## 3. Уровень 2: Тактический Исполнитель (Micro Executor)

Исполнитель решает задачу хода активного стека. Он выбирает действие на основе **9 универсальных тактических паттернов**:

### 9 Атомарных тактических паттернов:
1. **`BLOCK_SHOOTER`**: Встать на гекс, смежный с чужим стрелком (штраф стрельбы 50%, запрет дальнего боя).
2. **`STRIP_RETALIATION`**: Нанести удар по цели перед атакой `ROLE_CORE`, чтобы разрядить её ответный удар.
3. **`BODYGUARD_SCREEN`**: Занять гекс на пути врага к `ROLE_CORE`, создавая физическую преграду.
4. **`BAIT_SACRIFICE`**: Встать в зону досягаемости вражеского тяжеловеса, вынуждая его пойти на дешёвый размен.
5. **`KITE_RETREAT`**: Переместиться на гекс, сохраняющий расстояние до ближайшего рукопашника $> \text{Speed}_{\text{enemy}}$.
6. **`STRIKE_PRIMARY`**: Атака приоритетной цели (цель без ответки или с максимальным уроном).
7. **`WAIT_TEMPO`**: Пропуск хода для заманивания врага и реализации «двойного хода» на стыке раундов.
8. **`TURTLE_DEFEND`**: Команда `DEFEND` (+20% к защите), когда перемещение ухудшает позицию.
9. **`SPELL_CAST`**: Применение магии контроля/баффа в критический момент.

### Функция полезности хода (Utility Function):
$$\text{Utility}(\text{Action}) = \sum_{i=1}^{9} w_i \times \text{Score}_i(\text{Action})$$

Веса $w_i$ **диктуются назначенной ролью стека и текущей фазой**:
- Для `ROLE_BAIT`: $w_{\text{BAIT}} = 1.0, w_{\text{STRIP}} = 0.9, w_{\text{STRIKE}} = 0.1$.
- Для `ROLE_INTERCEPTOR`: $w_{\text{BLOCK}} = 1.0, w_{\text{WAIT}} = 0.7, w_{\text{DEFEND}} = 0.0$.
- Для `ROLE_CORE`: $w_{\text{KITE}} = 1.0, w_{\text{STRIKE}} = 0.9, w_{\text{BAIT}} = -10.0$.

## 4. Пайплайн обучения (Training Pipeline)

Обучение строится по схеме **Hierarchical Reinforcement Learning (HRL)** с **Reward Shaping**:

```
[ Генератор случайных боев (VCMI Battle Spawner) ]
                     │
                     ▼
[ Наблюдение поля боя: 15x11 + Статы 14 стеков ]
                     │
                     ▼
┌────────────────────────────────────────────────────────┐
│ ВЕРХНИЙ СЛОЙ (Director): Предсказывает роли стеков     │
│ Выход: [Роль_1, Роль_2, ... Роль_N]                   │
└────────────────────┬───────────────────────────────────┘
                     │ Вектор целей
                     ▼
┌────────────────────────────────────────────────────────┐
│ НИЖНИЙ СЛОЙ (Executor): Фильтрация ходов по 9 паттернам│
│ Генерация 3-4 лучших гексов -> Выбор лучшего действия  │
└────────────────────┬───────────────────────────────────┘
                     │ Действие в движок VCMI
                     ▼
[ Расчет плотных наград (Reward Shaping) и обновление весов ]
```

### Награды (Reward Function):
- **$+100$**: Успешная блокировка чужого стрелка.
- **$+150$**: Вражеский сильный стек потратил ход/удар на единичку ценностью $<50$ золота.
- **$+80$**: Удар по врагу без получения ответного урона.
- **$-200$**: Потеря единиц из стека `ROLE_CORE`.
- **$+500$**: Полная победа в бою с 0 потерь в `ROLE_CORE`.
